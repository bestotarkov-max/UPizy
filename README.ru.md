# UPizy

Повышение разрешения видео: **720p / 1080p → 2K (1440p) / 4K (2160p)** — и, по желанию,
плавность 60/120 fps.

Нативный Windows-инструмент на **Rust**: один `.exe`, без Python, без Visual Studio и без
установки зависимостей. Четыре движка апскейла на выбор:

| Движок | Что делает | Когда использовать |
|---|---|---|
| **AI (Real-ESRGAN)** | Нейросеть дорисовывает детали: текстуры, грани, лица, текст | Клипы, аниме, скринкасты, короткие ролики |
| **Аниме (Anime4K)** | Те же нейросети, но скомпилированные в GLSL-шейдеры: `Restore_CNN` + `Upscale_CNN_x2` прямо в конвейере ffmpeg | Аниме и мультфильмы: серия за 15–20 минут |
| **GPU (libplacebo)** | `ewa_lanczossharp` + deband + dither в Vulkan: чисто, без «фантазий», очень быстро | Полнометражные фильмы, сериалы, всё длинное |
| **Турбо (CUDA)** | Декодирование → `scale_cuda` lanczos → NVENC: всё на видеокарте | Когда нужно «прямо сейчас»: целый фильм за минуты |

Дополнительно — **интерполяция кадров RIFE** (×2 / ×4, по умолчанию **выключена**):
плавность как у 60/120 fps без «мыла», отдельно или вместе с апскейлом.

Интерфейс переключается между **русским и английским** кнопками `RU` / `EN` в заголовке окна.
При первом запуске язык выбирается по языку системы (русский Windows — русский интерфейс,
остальные — английский).

---

## Быстрый старт

1. Скачайте архив `UPizy-<версия>-win64.7z` и распакуйте в любую папку.
2. Запустите `UPizy.exe`.
3. При первом запуске установите **ffmpeg** (см. [Требования](#требования)) — программа
   проверит окружение и напишет в лог, чего не хватает.
4. Нужен AI-движок? Кнопка **«Скачать AI»** в правом верхнем углу (~45 МБ, один раз).
   Нужна плавность? **«Скачать RIFE»** в блоке «Плавность» (~410 МБ, один раз).
5. Перетащите видео в окно → выберите цель (2K/4K) → **Запустить**.

Результат по умолчанию сохраняется рядом с исходником: `фильм_4K.mkv`.

> AI/RIFE-движки скачиваются приложением в папку `bin\` рядом с `UPizy.exe`.
> В архив они не входят: программу можно распространять без сотен мегабайт моделей.

## Что умеет

- **Любые входные форматы** — декодирование на стороне ffmpeg.
- **Апскейл в 2K / 4K / ×1.5 / ×2 / ×3 / своё разрешение**, пропорции сохраняются,
  анаморфный SAR и поворот телефона учитываются.
- **Кодирование**: H.265 NVENC (GPU), H.264 NVENC, x265, x264, AV1 (SVT) — выбор или «авто».
- **10-битный вывод** (меньше бандинга в градиентах) для 2K/4K и HDR.
- **Сохранение всего**: аудио (copy), субтитры, главы, метаданные, обложки/шрифты в MKV.
  Для MP4 — совместимые дорожки, несовместимые аккуратно конвертируются.
- **HDR**: по умолчанию корректный tone-mapping в SDR (bt.709); режим «Сохранить HDR»
  оставляет BT.2020/PQ и 10 бит (только GPU-движок).
- **Интерлейс**: автоматический `bwdif` перед апскейлом.
- **Плавность ×2 / ×4** (RIFE, опционально): 24 → 48, 30 → 60, 60 → 120 fps и т. д.
  Работает и без апскейла — режим «Без апскейла — только плавность».
- **Пакетная обработка**, drag & drop, прогресс с ETA, лог, отмена.
- **Потоковый конвейер** для AI: кадры идут через память блоками, диск не забивается
  (для 4K-фильма не нужно терабайта свободного места).
- **Возобновляемость**: готовые файлы помечаются, повторный запуск их пропускает.
- **Два языка интерфейса**: русский и английский, переключаются на лету.

## Скорость и качество (замеры)

Железо: Ryzen 5 5600, RTX 2080 Ti 11 ГБ, 32 ГБ RAM. Источник: 720p, 30 fps, 90 кадров.

| Режим | Время на 90 кадров | Приблизительно |
|---|---|---|
| ТУРБО · CUDA → 4K | **1.1 с на 96 кадров** | ~85 кадров/с, 23-минутная серия ≈ **7 мин** |
| GPU · libplacebo → 4K | **4.7 с** | ~19 кадров/с, часовой фильм ≈ 1.3 ч |
| AI · animevideo v3 ×3 → 4K | **25 с** | ~3.6 кадра/с, часовой фильм ≈ 6–7 ч |
| AI · animevideo v3 ×2 → 2K | **16 с** | ~5.6 кадра/с |
| AI · x4plus → 2K/4K | **~376 с** | ~0.25 кадра/с — только для коротких клипов |

Вывод: **AI — для качества на клипах и аниме, GPU-режим — для длинных фильмов,
Турбо — когда ждать некогда.** Турбо визуально чуть мягче libplacebo (нет deband и CAS),
но это не «мыло»: края и текст остаются ровными, разница видна только при сравнении кадров рядом.

Типичный прирост:

- 720p → 1440p: AI-модель работает ровно в ×2, без промежуточного ресемплинга.
- 720p → 2160p: ×3, тоже без остатка.
- 1080p → 2160p: ×2.
- Для x4plus результат считается в ×4 и аккуратно уменьшается до цели (суперсэмплинг).

### Сколько ждать серию (23 минуты, 1080p)

| Режим | Скорость | На 23 минуты |
|---|---|---|
| **Турбо → 4K, без плавности** | ~117 кадров/с | **≈ 5 минут** |
| **Аниме (Anime4K S) → 4K** | ~31 кадр/с | ≈ 18 минут |
| **Аниме (Anime4K M) → 4K** | ~28 кадров/с | **≈ 20 минут** |
| **Аниме (Anime4K L) → 4K** | ~25 кадров/с | ≈ 22 минуты |
| GPU libplacebo → 4K, без плавности | ~31 кадр/с | ≈ 17 минут |
| AI animevideo → 4K, без плавности | 2.9 кадра/с | ≈ 3 часа |
| GPU → 4K + плавность ×2 | — | ≈ 2 ч 20 мин |
| **Аниме (Anime4K) → 4K + плавность ×2** | — | **≈ 2 ч 40 мин** |
| AI → 4K + плавность ×2 | 1.1 кадра/с | ≈ 8 ч 15 мин |

Плавность упирается в RIFE: он один съедает около двух часов на серию (≈5 кадров/с при
1080p). Скорость зависит от контента: на шумном/фото-материале NVENC и libplacebo
работают на 20–40 % медленнее, чем на чистом аниме.

## Аниме: движок Anime4K

Пункт **«Движок» → «Аниме · Anime4K»**. Это те же нейросети для аниме, что и в
Real-ESRGAN, но собранные не в отдельный процесс ncnn, а в **GLSL-шейдеры** (формат mpv
`.hook`), которые выполняет libplacebo прямо внутри ffmpeg.

Почему это в 10 раз быстрее AI-режима:

- нет второго процесса и повторной загрузки модели — всё идёт одним конвейером ffmpeg;
- кадры **не ходят через PNG-файлы** на диске (у AI-пути это ~40 % времени: запись,
  чтение и повторная распаковка 4K-PNG);
- шейдер считает один проход по пикселям вместо блочной обработки каталогами.

Что внутри (порядок важен, шейдеры склеиваются в один файл):

| Проход | Шейдер | Зачем |
|---|---|---|
| 1 | `Clamp_Highlights` | гасит пересветы, чтобы не было белых ореолов на бликах |
| 2 | `Restore_CNN` | убирает звон и «дрожание» контуров, восстанавливает тонкие линии |
| 3 | `Upscale_CNN_x2` | апскейл ×2 с учётом краёв; для 720p → 4K запускается дважды |

Варианты **S / M / L** — сети одного типа, но разного размера: S быстрее всех и чуть
мягче, L детальнее и на ~20 % медленнее, M — баланс по умолчанию.

Честно о границах: Anime4K сделан под **рисованный контент** — линии, заливки, текст.
На фото, коже, шумах и мелких текстурах Real-ESRGAN всё ещё даёт больше, поэтому
AI-движок остаётся для клипов и скринкастов. На аниме разница между ними видна только
при сравнении кадров вплотную.

Шейдеры распространяются по лицензии **MIT** (© 2019–2021 bloc97), вкомпилированы
в `.exe` — отдельные файлы рядом с программой не нужны.

## Плавность: интерполяция кадров

Пункт **«Плавность · интерполяция кадров»** в настройках: `Выключена` (по умолчанию),
`×2` или `×4`. Это независимая опция — можно включить только её (цель «Без апскейла —
только плавность») или совместить с любым апскейлом.

**Движок — RIFE (rife-ncnn-vulkan)**, а не блендинг ffmpeg. Это принципиально:

| | RIFE (по умолчанию) | minterpolate (запасной вариант) |
|---|---|---|
| Что делает | Нейросеть восстанавливает движение и дорисовывает кадр | Ищет векторы движения эвристикой |
| Аниме, линии, текст | Чёткие, без двоений | Артефакты «желе», рваные линии |
| Скорость (720p) | ~15–20 кадров/с на 2080 Ti | В разы медленнее и хуже |
| Нужна установка | ~410 МБ (кнопка «Скачать RIFE») | Встроено в ffmpeg |

Если RIFE не установлен, программа честно пишет в логе, что работает minterpolate,
и предлагает кнопку загрузки. Модели: **rife-anime** (аниме/мультфильмы, выбирается
автоматически для аниме-моделей апскейла) и **rife-v4.6** (обычное видео).

Порядок операций: **интерполяция в исходном разрешении → апскейл**. Так RIFE считает
меньше пикселей (быстрее и точнее по движению), а апскейл уже размножает готовые кадры.
×4 выполняется двумя проходами ×2.

Режимы:

| Настройка | Результат |
|---|---|
| Плавность ×2, цель 4K | `фильм_4K_60fps.mkv` — 4K и 60 fps |
| Плавность ×2, цель «только плавность» | `фильм_60fps.mkv` — размер кадра не меняется |
| Плавность выключена | как раньше, `фильм_4K.mkv` |

Мелочи, которые стоит знать:

- На стыках внутренних блоков обработки дубли кадров вырезаны — нет «стоп-кадров»
  и рывков (проверено по разнице соседних кадров).
- Итоговое число кадров — `2N − 1` (×2) и `4N − 3` (×4): последний кадр не дублируется,
  поэтому видео короче исходного примерно на один кадр. Длительность звука не меняется.
- ×3 нет: RIFE удваивает, поэтому доступны только ×2 и ×4.
- RIFE и Real-ESRGAN работают в 8-битном SDR, поэтому HDR-источник при интерполяции
  тонально отображается в bt.709 (как и в AI-режиме).

## CLI

```bat
upizy-cli.exe --help

:: 4K из 1080p, максимальное качество AI
upizy-cli.exe --target 4K --quality max "video.mp4"

:: быстрый GPU-апскейл целого фильма в 2K, MKV
upizy-cli.exe --target 2K --engine fast "film.mkv"

:: турбо: 4K за минуты (всё на GPU, чуть мягче libplacebo)
upizy-cli.exe --target 4K --engine turbo "series_ep01.mkv"

:: аниме: нейросетевые шейдеры Anime4K — серия за ~20 минут
upizy-cli.exe --target 4K --engine anime4k --a4k M "series_ep01.mkv"

:: аниме, AI + аниме-модель, вывод в папку
upizy-cli.exe --target 4K --model realesrgan-x4plus-anime -o D:\out "series_ep01.mkv"

:: только плавность: 30 → 60 fps, разрешение не меняем
upizy-cli.exe --target keep --interp 2 "anime.mkv"

:: 4K + 60 fps, аниме-модель интерполяции
upizy-cli.exe --target 4K --interp 2 --interp-model rife-anime "anime.mkv"

:: своё разрешение и H.264 для совместимости
upizy-cli.exe --target custom --width 3200 --height 1800 --encoder h264_nvenc --container mp4 "clip.mov"

:: диагностика окружения
upizy-cli.exe --list
```

Основные флаги: `--target`, `--engine ai|fast|turbo|anime4k`, `--a4k S|M|L`, `--model`,
`--quality max|high|balanced`, `--encoder`, `--container mkv|mp4`, `--interp 1|2|4`,
`--interp-model auto|rife-anime|rife-v4.6`, `--no-interp`, `--sharpen 0..1`, `--denoise`,
`--hdr tonemap|preserve`, `--output`, `--overwrite`, `--keep-work`, `--install-ai`,
`--install-rife`, `--list`.

Язык сообщений CLI: переменная окружения `UPIZY_LANG=ru|en`
(иначе берётся язык из `settings.json`).

## Требования

- **Windows 10/11 x64.**
- **ffmpeg + ffprobe в PATH** (сборка с NVENC/Vulkan — например, `ffmpeg-full` от
  [gyan.dev](https://www.gyan.dev/ffmpeg/builds/)). Можно положить `ffmpeg.exe` и
  `ffprobe.exe` в папку `bin\` рядом с программой.
- Для AI-движка — видеокарта с **Vulkan** (NVIDIA/AMD/Intel). Скачивается по кнопке.
- Для интерполяции — та же видеокарта с Vulkan, движок RIFE (~410 МБ) по кнопке.
- Для H.265 NVENC — NVIDIA Turing или новее.

Проверка окружения:

```bat
upizy-cli.exe --list
```

## Сборка из исходников

Нужен только Rust (GNU-тулчейн, **Visual Studio не требуется**):

```bat
winget install Rustlang.Rustup
rustup default stable-x86_64-pc-windows-gnu

build.bat
```

Результат: `target\release\upizy.exe` (GUI) и `upizy-cli.exe` (консоль);
`build.bat` копирует их в корень проекта как `UPizy.exe` и `UPizy-cli.exe`.

Аргументы сборки, использованные для релиза (убирают личные пути из бинарника):

```bat
set RUSTFLAGS=--remap-path-prefix=%USERPROFILE%\UPizy=upizy --remap-path-prefix=%USERPROFILE%=C:\src
cargo build --release
```

### Как устроен AI-конвейер

```
ffmpeg (decode → PNG в pipe)
   └─► Rust режет поток на кадры, пишет блок по 16–96 кадров
         └─► realesrgan-ncnn-vulkan (блок целиком, GPU)
               └─► Rust подаёт PNG в stdin второго ffmpeg
                     └─► ffmpeg: scale до цели → CAS → HEVC 10-bit + аудио/субтитры
```

Один проход кодирования, никакой сборки сегментов, ограниченное потребление диска
и точное сохранение числа кадров и длины.

С интерполяцией в конвейер добавляется ещё одна ступень:

```
ffmpeg (decode → PNG)  ─►  RIFE ×2/×4 (блоками, GPU)  ─►  Real-ESRGAN (опционально)  ─►  ffmpeg (encode + звук/субтитры)
```

RIFE работает блоками по 8–120 кадров (в зависимости от разрешения): один кадр
переносится в следующий блок, а дубли на стыках удаляются, поэтому панорамы идут
без рывков.

## Ограничения (честно)

- **VFR** (переменный fps) приводится к постоянному — для экранных записей и большинства
  фильмов это незаметно.
- **AI + HDR**: нейросеть работает в 8-битном SDR, поэтому HDR-источник тонально
  отображается в bt.709. Нужен HDR на выходе — используйте GPU-режим и «Сохранить HDR».
- **Дорожка Dolby Vision** не переносится (метаданные DV теряются).
- **Многоканальный звук** копируется как есть; в MP4 несовместимые кодеки (DTS, TrueHD)
  перекодируются в AAC 320k.
- AI-апскейл 4K-фильма займёт часы — это ограничение скорости нейросети, а не программы.
- **Турбо**: без deband и CAS (поэтому чуть мягче), 8/10 бит, HDR-источники
  автоматически обслуживаются обычным GPU-путём с tone-mapping. Если в системе нет
  NVENC или фильтра `scale_cuda`, режим сам откатывается на libplacebo и пишет об этом в лог.
- **Anime4K** требует фильтр `libplacebo` и работающую Vulkan-видеокарту; без них
  движок откатывается на обычный libplacebo (в логе будет строка об этом).
  Выход — 8/10 бит; на слабых видеокартах для длинных задач лучше вариант `S`.
